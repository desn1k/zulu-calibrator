# Алгоритм калибровки ЦТП в ZuluThermo

Oct 14, 2026 · @Andrew

Алгоритм сводит поверочный расчёт ZuluThermo с приборами учёта ЦТП и домов за 5–7 пересчётов. Каждый шаг меняет одну группу полей. Отработан на ЦТП Огородная, 87 (схема 2, замер 10.02.2026, Tнв −12,8): все расходы ±2 %, тепло ±4 %. Остальные 40 схем ЦТП и 48 схем потребителей описаны по справке Zulu и помечены «первая проверка», где поведение Zulu ещё не подтверждено расчётом.

## Назначение и границы

**Что калибруем:** второй контур ЦТП (отопление + ГВС) и дома за ним, по одному замеру (среднесуточному или часовому).

**Ограничения по умолчанию** (калькулятор держит их как флажки, снять может только пользователь):

- Qo\_r, Qgv\_sred домов не меняем никогда.
- Kso домов не меняем. Исключение — шаг 4, только по явному разрешению, с пометкой «нагрузка в модели ≠ договорной».
- Расчётный график домов T1\_r / T3\_r / T2\_r = 95 / 95 / 70 не меняем. В поверке он задаёт теплоотдачу системы, поэтому правка графика тоже подгоняет тепло, но ломает наладочный расчёт.
- Менять можно: испытательные параметры ТО и ступеней ГВС ЦТП, Kgv / Kcirc / Hcirc ГВС-объектов, шайбы ЦТП и домов, Kpoprav участков (шаг 6, по разрешению).

**Допуск:** 5 % по расходам, теплу и температурам. Цель шага — расход ±2 %.

**Порядок шагов:**

1. Шаг 0 — данные и мусор в полях; затем сброс к базе и выбор группы схемы ЦТП и каждого потребителя (разделы «Сброс к базе», «Схемы ЦТП», «Схемы потребителей»).
2. Шаг 1 — схема ЦТП, ТО отопления, ступени ГВС, Kgv.
3. Шаг 2 — циркуляция ГВС домов.
4. Шаг 3 — шайба ввода ЦТП.
5. Шаг 4 — тепло отопления домов (Kso, по исключению).
6. Шаг 5 — шайбы домов.
7. Шаг 6 — температуры через Kpoprav (по разрешению).

**Правило цикла:** после шага — поверочный расчёт → JSON → проверка критериев шага. Не сошлось — правим этот же шаг, к следующему не идём. Перед переходом калькулятор показывает вопросы по несостыковкам текущего шага.

## Входные данные и проверка приборов

До любых правок калькулятор сводит приборы в баланс. Прибор, который противоречит балансу, помечается и не идёт в цель подгонки.

**Что нужно на входе:**

| Точка | Поля |
| --- | --- |
| Ввод ЦТП (теплосеть) | G1, G2 т/ч; T1, T2 °C; P1, P2 м; Q Гкал/ч |
| Отопление после ЦТП | G3 (подача), G4 (обратка); T3, T4; P3, P4; Q прибора |
| ГВС на ЦТП | Tгв подачи, Tц циркуляции; Gп, Gц; Q; P по возможности |
| Дома | блоки приборов \_TS, \_OT, \_GVS (T1, T2, P1, P2, G1, G2, Q) |
| Режим | Tнв замера (столбец Tnv выгрузки), t подачи на источнике, t холодной воды, тип данных (сутки / час), единицы давления |

**Проверки (в этом порядке):**

| № | Проверка | Как считать | Норма | Если не сходится |
| --- | --- | --- | --- | --- |
| 1 | Тепло отопления ЦТП | Qсо = G3·(T3 − T4)/1000 | близко к Q прибора | Q прибора посчитано как G3·T3 − G4·T4 и завышено из-за разницы расходомеров → брать G·ΔT |
| 2 | Тепло ГВС ЦТП | Qгв = \[Gп·(Tгв − Tхв) − Gц·(Tц − Tхв)\]/1000 | ≈ Q прибора ГВС | подобрать Tхв (обычно 5) |
| 3 | Баланс ввода | Qввода vs Qсо + Qгв | ±2 % | искать ложный прибор |
| 4 | «Утечка» 2 контура | G3 − G4 ЦТП vs Σ(G1 − G2) домов | дома тоже теряют | дома возвращают почти всё → это ошибка расходомера ЦТП, утечки не подгонять |
| 5 | Расходы ЦТП vs дома | G3 vs ΣG1 домов отопления; Gп, Gц vs Σ ГВС-домов | ±3 % | отметить, какому верим |
| 6 | Потери квартальной сети | Qсо ЦТП − ΣQ отопления домов | 1–3 % | отрицательные = ошибка прибора |
| 7 | Разбор ГВС | (Gп − Gц) ЦТП vs Σ(G1 − G2) ГВС-домов | ±10 % | спросить, кому верим (цель Kgv) |
| 8 | Ступени ГВС | T2 ввода < T4 отопления | — | да → есть I ступень на обратке, схема двухступенчатая |
| 9 | Магистраль | T1 ввода vs t источника | T1 ≤ tист | T1 > tист → потери ≈ 0, разница = погрешность датчиков |
| 10 | Приборы ГВС-домов | G2 ≤ G1; P2 < P1; Tц < Tгв | — | нарушение → флажок, цель не ставить |
| 11 | Давления | модель − факт на подаче и обратке | — | одинаковый сдвиг → отметка манометров / H\_geo, в калибровку давления не вносить |

**Режим расчёта.** Данные суточные → нагрузка ГВС в поверке 100 % (средняя). Данные часовые → % нагрузки ГВС = Qгв факт / Qгв модель × 100 (настройки → ГВС → «Регулировать нагрузку ГВС», процент общий для сети). Tнв поверки = Tнв замера; t на источнике = факт за тот же период.

## Источники данных, GUID и неполные приборы

Модель ЦТП — из скопированной карточки Zulu; факт ЦТП — ручной ввод на первом экране; потребители — таблица из запроса с реальными именами полей, вставкой целиком.

**Факт ЦТП (первый экран).** Три блока, у каждого флажок «нет прибора»:

| Блок | Поля |
| --- | --- |
| Ввод | G1, G2, T1, T2, P1, P2, Q |
| Отопление после ЦТП | G3, G4, T3, T4, P3, P4, Q |
| ГВС ЦТП | Gп, Gц, Tгв, Tц, Pп, Pц, Q |
| Режим | Tнв замера, t подачи на источнике, Tхв, сутки / час, единицы давления |

**Факт потребителей (имена полей выгрузки).** Ключи: Sys, GUID, Bld, Name, N\_schem, CtpID / CtpName, DateMea, Tnv. Блоки приборов — T1 / T2 / P1 / P2 / dP / G1 / G2 / Q с суффиксами \_TS (ввод), \_OT (отопление), \_GVS, \_SV (вентиляция). Флаги TS / OTOP / GVS / VENT / HVS, Uchet, а также Qo\_fact / Qsv\_fact / Qgv\_fact / Qo\_dog и \*\_fact — не используются.

**Какой блок брать** (по схеме, а не по флагам):

1. ГВС-объект (схемы без отопления: 26, 27, 34, 46, 48) → \_GVS.
2. Объект отопления → \_OT; если пусто → \_TS (считаем только отоплением, с пометкой «взят ввод»).
3. Вентиляция → \_SV.
4. Объект с ИТП (отопление + ГВС в одной схеме) → \_OT и \_GVS; если есть только \_TS — делить и спрашивать (схемы потребителей).

**Редактирование.** Каждая ячейка факта потребителя правится руками: выбор блока, значение, «не доверять прибору». Правка помечается и сохраняется при повторной вставке выгрузки (ключ Sys).

**GUID.** Группа = GUID + тип системы.

- Разные типы под одним GUID — одно здание, разные системы: каждый объект берёт свой блок (Огородная: отопление + ГВС-кружок).
- Несколько объектов одного типа под одним GUID — многовводовый дом: в каждой строке записан один неделёный прибор на дом. Калькулятор делит его: G\_i = G · Qo\_r,i / ΣQo\_r (для ГВС — по Qgv\_sred·Kgv), Q так же, температуры и давления общие. Доли можно поправить руками. В баланс ЦТП прибор идёт один раз.
- Критерий шагов для многовводового дома: сумма модели по группе ±2 %, по каждому вводу ±5 %.
- Одинаковый факт у разных GUID — флажок «похоже на ошибку выгрузки».

**Неполные приборы ЦТП.** Недостающий блок восстанавливается из баланса или из суммы домов и помечается «расчётный»; допуск для него шире (±7 %).

| Чего нет | Чем заменяем | Что теряем |
| --- | --- | --- |
| Отопление после ЦТП | G3 = ΣG1\_OT домов; T3 = средняя T1 домов (вес по G) + 0,5–1 °C; T4 = средняя T2 домов; проверка Qсо = Qввода − QГВС | испытательные ТО — с погрешностью сети; дома без приборов досчитать по Qo\_r (kG) |
| ГВС ЦТП | Gп = ΣG1\_GVS, Gц = ΣG2\_GVS домов; Tгв = Tgv ЦТП (или max T1\_GVS + 1); Tц = средняя T2\_GVS − 1; Qгв = Qввода − Qсо | потери квартальной сети ГВС — оценка |
| Отопление и ГВС | оба блока из домов (как выше); замыкание по Qввода, разница = потери квартала (норма 1–5 %) | распределение потерь между СО и ГВС |
| Ввод | Qввода = Qсо + Qгв; T1 = t источника минус потери модели; G и T2 неизвестны | шайба ввода не подбирается (оставить или по наладочному расчёту); ступени — с недогревом 5 °C по умолчанию |
| Ничего по ЦТП | второй контур из домов, ввод — как строкой выше | ЦТП считается по домам; калькулятор предупреждает о низкой достоверности |

Если в схеме ЦТП нет ГВС (1, 4, 7, 21, 22) — блок ГВС скрыт, Qввода = Qсо. Дома без прибора в сумме домов досчитываются по доле нагрузки (Qo\_r или Qgv\_sred·Kgv) и получают общий множитель kG.

## Шаг 0 — мусор и ложные значения в полях

Калькулятор проходит карточку ЦТП и все строки потребителей и выдаёт список «поле → что не так → что сделать». Ничего не правит сам: часть пунктов — вопросы пользователю.

**Карточка ЦТП:**

| Признак | Правило | Действие |
| --- | --- | --- |
| Схема не совпадает с результатом | N\_schem = 2 (или другая двухступенчатая), а Gverh = 0 и T11\_niz ≈ T1 ввода | расчёт сделан по параллельной схеме или не пересчитан → пересчитать, проверить N\_schem |
| Испытательные параметры ступеней не стыкуются | T22\_i\_niz > T21\_i\_verh; Q\_i\_niz или Q\_i\_verh больше всего Q ГВС; типовые «70 → 40 / 5 → 60» | пересчитать в шаге 1 из факта |
| Недогрев ТО отопления | T12\_i − T21\_i < 2 °C | физически невозможно, Zulu выведет огромный k → шаг 1 |
| G1\_i ТО отопления | в смешанной схеме G1\_i = весь ввод | должно быть G1 − расход II ступени → шаг 1 |
| Hsec\_so, Hsec\_niz, Hsec\_verh | 0 или пусто | поставить всю потерю ТО в Hsec, Nsec = Ngr = 1 (рекомендация справки); иначе шайба ввода будет неверной |
| Qgv\_sred ЦТП | стоит любое значение при нарисованной сети ГВС | используется только без вспомогательного участка → не трогать |
| Regul\_G ЦТП | это способ дросселирования 0–6, не регулятор | 5 = общая шайба на вводе на подающем; показывать расшифровку |
| Hgv2\_ras / Hgv2\_obr | не замер | сверить с домом, у которого есть давления ГВС; давления ГВС не цель |
| Давления 1 контура | одинаковый сдвиг модель − факт на подаче и обратке | отметка манометров; Pcalibr не заполнять |
| Gset\_nal, элеваторные поля | результаты старой наладки | справочно, не влияют |

**Потребители:**

| Признак | Правило | Действие |
| --- | --- | --- |
| Нет привязки к ЦТП | CtpID / CtpName пусто, OTOP / GVS = null | исправить в базе |
| Qo\_dog ≠ Qo\_r | расхождение в разы (0,82 против 0,09) | опечатка; верная та, что сходится с прибором при расчётной t |
| Qo\_fact | расходится с прибором | Zulu не использует, игнорировать |
| Kso ≠ 1 | источник неизвестен | спросить: из базы / договора или след прошлой подгонки |
| Kgv, Kcirc, Tcirc, Tgv менялись по кругам | журнал показывает колебания | вернуть базовые до шага 1 |
| T1\_r / T3\_r / T2\_r | не 95 / 95 / 70 у схемы 4 | вернуть расчётный график |
| Regul\_T = 1 у дома без ГВС | это регулятор ГВС, не отопления | безвредно, пометить |
| Regul\_G дома | 0 нет · 1 расход · 2 погодный · 3 давление в обратке · 4 приоритет шайбы | спросить, есть ли реальные регуляторы; АУУ с насосом → схема 5 |
| ГВС-объект без циркуляции | нет G2 или G2 = 0 | спросить: тупиковая схема или нет прибора |
| Hcirc = 0,1 | заглушка | заполняется в шаге 2 |
| Шайбы удалены | Dshb\_so\_pod\_u пусто при большом расходе | подбираются в шаге 5 после шайбы ЦТП |

## Шаг 1 — схема ЦТП, ТО отопления, ступени ГВС, Kgv

Испытательные параметры всех трёх теплообменников ЦТП = фактический режим замера, сведённый в баланс расходов и тепла. Тогда Zulu при любой Tнв пересчитывает аппараты от реальной точки.

**1.1 Схема.** Номер выбирается по температурам, а не по паспорту: T2 ввода < T4 отопления → есть I ступень на обратке.

| N\_schem | Схема ЦТП (справка Zulu) | Когда |
| --- | --- | --- |
| 2 | двухступенчатая смешанная ГВС, независимое СО и СВ | T2 ввода < T4, ступени не в серии с ТО отопления |
| 3 | параллельная ГВС, независимое СО и СВ | T2 ввода ≥ T4 |
| 15 | двухступенчатая последовательная ГВС, независимое СО | весь ввод идёт через ТО отопления (не отработано) |
| 20 | последовательное подключение ГВС, независимое СО и СВ | то же (не отработано) |

\_niz = I (нижняя) ступень, \_verh = II (верхняя). Как Zulu разводит воду в схеме 2 (проверено на расчётах):

- сетевая подача делится: ТО отопления (G1\_i) и II ступень (Gверх); после них потоки смешиваются и все идут через I ступень на обратку;
- по второму контуру через I ступень идёт ТОЛЬКО разбор (холодная вода), циркуляция подмешивается перед II ступенью.

**1.2 Расчёт испытательных параметров (схема 2).** Обозначения: G, T1, T2 — ввод; G3, T3, T4 — отопление; Gп, Gц, Tгв, Tц — ГВС ЦТП; Gр = Gп − Gц (разбор). Свободных параметра два: T22\_niz и T12\_verh.

1. Отопление: Qсо = G3·(T3 − T4)/1000.
2. I ступень: T21\_niz = Tхв; T22\_niz — выбор (на 1,5–2 °C ниже T11\_niz); Q\_i\_niz = Gр·(T22\_niz − Tхв)/1000; T12\_niz = T2\_bal (T2 ввода, сведённая в баланс, см. ниже); T11\_niz = T12\_niz + 1000·Q\_i\_niz/G.
3. II ступень: T21\_verh = (Gр·T22\_niz + Gц·Tц)/Gп; T22\_verh = Tгв; Q\_i\_verh = Gп·(Tгв − T21\_verh)/1000; T11\_verh = T1; T12\_verh — выбор (≥ T21\_verh + 2); Gверх = 1000·Q\_i\_verh/(T1 − T12\_verh).
4. ТО отопления: T11\_i = T1; T21\_i = T4; T22\_i = T3; G2\_i = G3; G1\_i = G − Gверх; T12\_i = (G·T11\_niz − Gверх·T12\_verh)/G1\_i.
5. Замыкание: G1\_i·(T1 − T12\_i)/1000 ≈ Qсо (±1 %) и T12\_i ≥ T21\_i + 0,8. Не сходится → сдвинуть T22\_niz / T12\_verh.

**T2 ввода сводится в баланс до расчёта ступеней:** T2\_bal = T1 − 1000·(Qсо + Q\_i\_niz + Q\_i\_verh)/G (Q\_i\_verh — из п. 3). Тогда тепло ввода G·(T1 − T2\_bal) равно Qсо + Q\_i\_niz + Q\_i\_verh. На странице шага калькулятор показывает обе величины: T2\_bal и T2 прибора.

Пример (Огородная, 87): Gр = 6,7; T22\_niz = 59 → Q\_i\_niz = 0,362; T2\_bal = 57,2 (прибор 57,0), T11\_niz = 60,9; T21\_verh = 55,1, Q\_i\_verh = 0,178; T12\_verh = 57,5 → Gверх = 5,6; G1\_i = 92,8, T12\_i = 61,1; замыкание 2,608 против 2,610.

Hsec\_so / Hsec\_niz / Hsec\_verh и Nsec / Ngr не меняются (если не 0). Regul\_T ЦТП = 1 (держит Tгв).

**1.3 Kgv ГВС-объектов.** Только там, где разбор модели отличается от прибора дома больше чем на 10 %:

```latex
K_{gv} = \frac{(G_1 - G_2)\,(T_{gv} - T_{hv})}{1000 \cdot Q_{gv\_sred}}
```

У тупикового объекта G2 = 0.

**Расход не измерен.** Если у ГВС-объекта G1\_GVS − G2\_GVS ≤ 0,05 т/ч или расхода нет, Kgv считается по теплу: Kgv = Q\_GVS / Qgv\_sred; строка помечается «по теплу (расход не измерен)». Нет и Q\_GVS — Kgv не выдаётся, вопрос пользователю. Пример (Огородная, 33567): 0,002 / 0,0277 ≈ 0,07.

Цель разбора = тот источник, который выбрал пользователь (проверка 7). Если верим домам, а разбор ЦТП больше, I ступень физически не охладит обратку до факта: T2 ввода останется выше на 1–2 °C, это принимаем.

**Не трогать на шаге 1:** Kso, нагрузки, шайбы, Hnz\_ras / Hnz\_obr, Hgv2\_ras / Hgv2\_obr, утечки, поля калибровки.

**Критерии шага 1:** Gverh > 0; T11\_niz ≈ расчётному (не T1); T3so\_t / T2so\_t ±0,7 °C; Gsum\_pod2 ±2 %; G ввода ±2 %; T2\_t ввода ±4 %. Qsum и T2 ввода ниже факта — нормально, закрывается шагами 2 и 4.

## Шаг 2 — циркуляция ГВС домов

Расчётный расход циркуляции делаем равным фактическому G2, а сопротивление — реальному располагаемому напору. Тогда Zulu считает потери циркуляции по Tcirc, и тепло ГВС ЦТП сходится.

**Признак проблемы:** Hcirc = 0,1 (заглушка) и Kcirc 20–60 %. Расчётный расход циркуляции маленький, фактический раздувается в √(H\_ras / 0,1) раз и случайно попадает в факт. Потери при этом считаются от маленького расхода: циркуляция в модели остывает на 0,7–1,8 °C против 5–12 °C по факту.

**Расчёт (режим Kcirc «по среднему расходу»):**

```latex
G_{gv} = \frac{1000 \cdot Q_{gv\_sred} \cdot K_{gv}}{T_{gv} - T_{hv}}, \qquad K_{circ} = 100 \cdot \frac{G_{2,\,факт}}{G_{gv}}
```

- Hcirc = H\_ras дома из последнего расчёта.
- Tcirc = T2\_GVS прибора (если уже равно — не трогать).
- Тупиковые объекты пропускаются.
- Kcirc 200–800 % — нормально для суточных данных: циркуляция идёт круглосуточно и в разы больше среднего разбора. Калькулятор не должен помечать это как ошибку.
- Режим «от тепловой нагрузки» даёт числа меньше, но включается для всей сети — не использовать.

**Поправка, если Gcirc ушёл больше чем на 10 %:** Hcirc\_нов = Hcirc · (Gмодель / Gфакт)².

**Не трогать:** Kgv, Tgv домов, Hgv2\_ras / Hgv2\_obr ЦТП.

**Критерии шага 2:** Gcirc ±10 % и Tcirc\_t ±1,5 °C у каждого дома; Q ГВС ЦТП (Q\_niz + Q\_verh) растёт к факту. Результат на Огородной: Gcirc ±3 %, Tcirc ±1 °C, Q ГВС 0,36 → 0,46.

## Шаг 3 — шайба ввода ЦТП

Шайба на вводе — единственное, что в модели держит расход ввода, если на ЦТП нет регулятора (RegulType = 0). Она изображает реальный регулятор расхода или перепада. Подбирается после шага 1 (нужны правильные Hsec) и до шайб домов.

**Поля:** Regul\_G = 5 (общая шайба на вводе, на подающем), Dshb\_pod\_u, Nshb\_pod\_u = 1. Результат: dHshb\_pod, H\_ras, Gsum\_pod.

**Подбор с нуля (шайбы нет или она удалена):**

1. Поверка с пустыми Dshb\_pod\_u / Nshb\_pod\_u → H\_ras и Gм. Без шайбы сопротивление ЦТП ΔH\_ЦТП = H\_ras − dHshb\_pod.
2. Если Gм ≤ Gф — шайба не нужна, расход ограничен выше (сеть, источник) → первый контур.
3. Напор, который гасит шайба при фактическом расходе, и диаметр (G т/ч, ΔH м, d мм):

```latex
\Delta H_{ш} = H_{ras} - \Delta H_{ЦТП} \left(\frac{G_ф}{G_м}\right)^2, \qquad d = 10 \sqrt[4]{\frac{G_ф^2}{\Delta H_{ш}}}
```

4. Поставить d, пересчитать. Формула даёт оценку с точностью \~5 % (H\_ras сам меняется с расходом), дальше поправка.

**Поправка установленной шайбы** (та же для шайб домов):

```latex
\Delta H_{ш,нов} = H_{ras} - (H_{ras} - \Delta H_ш)\left(\frac{G_ф}{G_м}\right)^2, \qquad d_{нов} = d \sqrt{\frac{G_ф}{G_м}} \sqrt[4]{\frac{\Delta H_ш}{\Delta H_{ш,нов}}}
```

Если ΔHш,нов ≤ 0 — шайбу убрать, расхода не хватает и без неё.

**Чувствительность:** dG/G ≈ 2 · (ΔHш / H\_ras) · dd/d. На Огородной (Ø72, ΔHш 3,1 из 5,0 м) ±1 мм ≈ ±1,7 % расхода ввода. Шайба ВВОДА почти не влияет на расходы домов и циркуляцию (их держат насосы ЦТП), только на температуры ЦТП и обратку ввода.

**Критерий шага 3:** G ввода ±2 % от прибора.

## Шаги 4–5 — тепло отопления домов и шайбы домов

Если расходы и подача домов сходятся, а обратка теплее и тепла меньше у всех одинаково, то теплоотдача систем в модели мала. Гидравликой это не лечится: в Zulu тепло дома меняют только Kso и расчётный график дома.

**Шаг 4 — варианты (выбирает пользователь):**

| Вариант | Что меняет | Цена |
| --- | --- | --- |
| А. Ничего (по умолчанию) | — | недобор тепла остаётся (на Огородной −15 %) |
| Б. Kso по исключению | Kso\_нов = Kso · Qфакт / Qмодель | нагрузка в модели не договорная; расчётный расход дома растёт → сопротивление системы падает → нужен шаг 5 |
| В. График T1\_r / T3\_r / T2\_r | поверхность приборов, расход не меняется | ломает наладочный расчёт, Tvso\_t 21–25 °C — не использовать |

Оба варианта Б и В подгоняют одну точку Tнв. Kso от погоды не зависит: при другой Tнв совпадёт, если доля перебора постоянная. Проверяется только вторым замером.

**Критерий шага 4 (вариант Б):** Q\_sum каждого дома ±5 %. На Огородной: −2…−4 %, Σ 2,48 против 2,57; расходы домов сдвинулись на 0…+8 %; T3so / T2so ЦТП просели на \~2 °C (дома берут больше, см. шаг 6).

**Шаг 5 — шайбы домов (Dshb\_so\_pod\_u, Nshb\_so\_pod\_u = 1):**

- менять только при |Gм / Gф − 1| > 2 %: шайба с малым dHshb\_so\_pod (< 2 м) резко реагирует на диаметр;
- есть шайба → формула поправки из шага 3 по H\_ras и dHshb\_so\_pod дома;
- шайбы нет → подбор с нуля из шага 3, где ΔH\_ЦТП заменяет сопротивление системы дома (H\_ras − dHshb\_so\_pod);
- шайбы домов — только после того, как сошёлся ввод ЦТП: до этого H\_ras домов неверный;
- дома без приборов — общий множитель расхода kG от баланса ЦТП (не отработано).

**Две шайбы подряд.** У потребителя есть шайба на вводе (Dshb\_pod / Nshb\_pod, Dshb\_obr / Nshb\_obr — общая на все системы) и шайба на СО (Dshb\_so\_pod\_u / Dshb\_so\_obr\_u). Zulu учитывает обе (проверено на Огородной: H\_ras = dH шайбы СО + dH шайбы ввода + потери СО).

- У дома только с отоплением шайбы стоят последовательно и дублируют друг друга → заменить одной на СО с эквивалентным диаметром, шайбу ввода очистить (Dshb\_pod и Nshb\_pod пусто). Расход не меняется.
- У дома с несколькими системами на одном вводе (открытое ГВС, вентиляция) обе нужны: вводная ограничивает весь дом, шайба СО — только отопление.
- Nshb без диаметра (или диаметр без Nshb) — мусор, очистить оба поля.

```latex
d_{экв} = \left(d_1^{-4} + d_2^{-4}\right)^{-1/4}, \qquad \Delta H_ш = \frac{10^4\,G^2}{d^4}
```

**Критерий шага 5:** Gso каждого дома ±2 %, Gsum\_pod2 ЦТП ±1 %, тепло домов не уходит. На Огородной: 4 шайбы из 8, расходы −1,3…+1,8 %.

## Шаг 6 — температуры через Kpoprav (отложено, не отработано)

Шаг добивает остаточный сдвиг температур (на Огородной отопление −2 °C, тепло домов −3 %). Выполняется только с разрешения пользователя; калькулятор сначала спрашивает, есть ли на магистрали другие ЦТП и потребители.

```latex
K_{poprav,нов} = K_{poprav} \cdot \frac{\Delta T_ф}{\Delta T_м} \cdot \frac{G_ф}{G_м}
```

| Порядок | Участки | ΔT факт | ΔT модель | Особенности |
| --- | --- | --- | --- | --- |
| 1 | Магистраль источник → ЦТП | tист − T1 ввода | tист − T1\_t ЦТП | T1 > tист → ΔTф ≈ 0,3 °C (не 0); задевает соседей |
| 2 | Квартальная сеть отопления | T3 ЦТП − средняя T1 домов (вес по G) | то же по модели | брать подачу: обратка по приборам часто несостоятельна |
| 3 | Квартальная сеть ГВС | Tгв ЦТП − T1\_GVS дома | Tгв ЦТП − T1\_t дома | по веткам к тупиковым объектам и домам с перебором тепла ГВС |

На Огородной: магистраль 88,7 → 87,8 в модели против 89,2 по прибору; тупиковая Огородная, 83 — 57,7 в модели против 53,2.

**Критерии шага 6:** T1\_t ЦТП ≥ tист − 0,5; T3so / T2so ±1 °C; T1 домов ±0,5 °C; Tгв тупиковых ±1,5 °C; тепло и расходы из шагов 4–5 не уходят.

**После всех шагов — проверка вторым днём.** Поменять только Tnv\_t, t на источнике и % ГВС, поверка, сравнение с приборами того дня. В пределах 5–7 % — подгонка держится.

## Схемы ЦТП — все 41

Каждая схема ЦТП = способ присоединения отопления × способ приготовления ГВС. Калькулятор по N\_schem берёт строку (процедура отопления) и столбец (процедура ГВС) из таблицы ниже и складывает их. Описания схем — по справке Zulu; проверена на практике только схема 2, остальные помечаются «первая проверка», пока не отработаны.

| Отопление ↓ / ГВС → | нет | параллельная | 2-ст. смешанная | 2-ст. последовательная | 1-ст. последовательная | открытый водоразбор | бак-смеситель | сетевая вода без регулятора |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Независимое (ТО) | 1 | 3 | 2 | 15 | 20 | 37 | 30 | — |
| Непосредственное | — | 6 | 5 | 12 | 16 | 17 | 29 | — |
| Групповой элеватор | 4 | 11 | 10 | 13 | 18 | 36 | 31 | — |
| Насос смешения на перемычке | 7 | 9 | 8 | 14 | 19 | 33 | 32 | — |
| Насос смешения на подающем | 21 | 23 | 25 | 27 | — | 34 | — | 38 |
| Насос смешения на обратном | 22 | 24 | 26 | 28 | — | 35 | — | 39 |

Отдельно: **40** — регулятор давления на подающем, **41** — на обратном (не тепловой пункт, а узел сети). Схема 29 — бак-смеситель, ветка отопления проходит без изменений. 38 / 39 работают только с Regul\_T = 0. Контур ГВС в схемах 29–32 подключается вспомогательным участком.

**Обозначения** (как в шаге 1): G, T1, T2 — ввод; G3, T3, T4 — отопление после ЦТП; Gп, Gц, Tгв, Tц, Gр = Gп − Gц — ГВС; Qсо = G3·(T3 − T4)/1000. **Tо** — температура сетевой воды, выходящей из отопления: T12\_i при независимом, T4 при зависимом (элеватор, насос, непосредственное). **Gсо** — сетевая вода на отопление.

### Отопление ЦТП — по строкам

| Строка | Что считать | Что подгонять |
| --- | --- | --- |
| Независимое | испытательные ТО: T21\_i = T4, T22\_i = T3, G2\_i = G3, T11\_i = t входа в ТО (T1, а в последовательных — после II ст.), G1\_i и T12\_i — из столбца ГВС | Hnz\_ras = P3 − P4, Hnz\_obr = H\_geo + P4; шайба ввода (шаг 3) |
| Непосредственное | во второй контур идёт сетевая вода: Gсо = G3, T3 = T1 (или t после II ст.) | шайба ввода; расходы домов — их шайбами |
| Групповой элеватор | uф = (Tвх − T3)/(T3 − T4); Gсо = G3/(1 + uф) | Dsop\_u (сопло) и Nel\_u — по формулам элеватора ниже; Hnz\_obr |
| Насос смешения (перемычка / подающий / обратный) | uф — как у элеватора; Gсо = G3/(1 + uф) | Hnz\_ras (напор 2 контура после насоса) так, чтобы G3 = факт; Hnz\_obr = H\_geo + P4; шайба ввода — на Gсо. Первая проверка |
| 40 / 41 | — | RegulVal = H\_geo + P факта за регулятором; Kreg (kvs) ≥ G / √ΔP, ΔP в бар |

Погодный регулятор на ЦТП (если есть на месте): RegulType = 1, TGraph, Tcut / Tshelf, Regul\_G\_kvs. Без него T3 задаётся испытательными параметрами и сетью.

**Элеватор** (методика контекста; Gс — сетевая вода на СО т/ч, h — потери в СО после элеватора м, H — напор перед соплом м):

```latex
u = 1{,}15\,\frac{T_1 - T_3}{T_3 - T_4}, \quad d_г = 8{,}5\sqrt[4]{\frac{G_с^2 (1+u)^2}{h}}, \quad d_с = 9{,}6\sqrt[4]{\frac{G_с^2}{H}}, \quad H_{min} = 1{,}4\,h\,(1+u)^2
```

Поправка установленного сопла: dс,нов = dс · √(Gф / Gм). Номер элеватора по горловине: № 1–7 = 15 / 20 / 25 / 30 / 35 / 47 / 59 мм. Сопло не меньше 3 мм, округление вниз до 0,1 мм.

| Бак-смеситель (29–32) | бак смешивает подачу, обратку и циркуляцию так, чтобы на ГВС была Tgv. Поля: Tgv; далее Kgv (1.3) и Kcirc / Hcirc (шаг 2) ГВС-объектов |
| Сетевая вода без регулятора (38, 39) | Regul\_T = 0 обязательно; иначе схема «сливает» теплоноситель за перемычку. Испытательные \_niz — как у параллельной. Первая проверка |

**Выбор схемы по приборам, если N\_schem сомнителен:** G1 − G2 ввода ≈ разбор → открытая; T3 ≈ T1 → непосредственное; G3 > G и T3 < T1 без ТО → элеватор или насос; P3 − P4 выше P1 − P2 → есть насос или ТО; T2 < T4 → I ступень на обратке. Окончательно — обследование.

## Схемы потребителей — все 49

Та же логика, что у ЦТП: строка = отопление, столбец = ГВС. По справке Zulu схемы универсальны: незаполненная вентиляция не считается, а в схемах 1–6 не считается ГВС без данных. Поэтому дома только с отоплением часто стоят на схемах 1–6 (как схема 4 на Огородной).

| Отопление ↓ / ГВС → | нет | открытый водоразбор | параллельная | 2-ст. смешанная | 2-ст. последовательная | 1-ст. последовательная |
| --- | --- | --- | --- | --- | --- | --- |
| Независимое (ТО) | 1, 3 без ГВС | 1, 3 | 20, 22 | 14, 16 | 8, 10 | 31 |
| Непосредственное | 45; 4 без ГВС | 4 | 28 | 32 | 33 | 35 |
| Элеватор | 2, 6 без ГВС | 2, 6 | 19, 24 | 13, 18 | 7, 12 | 29 |
| Насос на перемычке | 5 без ГВС | 5, 47 | 21, 23 | 15, 17 | 9, 11 | 30 |
| Насос на подающем | — | 36 | 38 | 40 | 42 | — |
| Насос на обратном | — | 37 | 39 | 41 | 43 | — |
| Без отопления | — | 26 (с циркуляцией), 46, 48 (подмес из обратки) | 27 | 34 | — | — |

Отдельно: **25** — только вентиляция; **49** — вентиляция после насосного смешения; **44** — подключение к обратному трубопроводу (поверхность СО считается от 70 °C, насос покрывает потери СО). Вентиляция есть в схемах «СО и СВ» (1, 9, 10, 15, 16, 21, 22, 31, 47).

### ГВС потребителя — по столбцам

| Столбец | Что делать |
| --- | --- |
| Открытый водоразбор (1–6, 26, 36, 37, 46–48) | разбор = G1 − G2 прибора ГВС (или ТС, если общий) — не утечка. Kgv — формула 1.3; Kcirc / Hcirc / Tcirc — шаг 2; Tgv; Regul\_T: 1 регулятор, 2 из подачи, 3 из обратки, 4 только подача (шайба циркуляции не подбирается), 5 регулятор на обратке (Regul\_T\_kvs); Hpump\_gvs — повысительный насос; шайбы Dshb\_gvs\_u / Dshb\_circ\_u. Схема 26 — ГВС-объекты за ЦТП (отработано на Огородной) |
| Параллельная (19–24, 27, 28, 38, 39) | формулы столбца «параллельная» ЦТП с приборами дома (ТС — ввод, \_GVS — ГВС) → испытательные \_niz дома. Без испытательных Zulu берёт «зашитые» 70 → 30 и Tхв / Tгв источника — не оставлять |
| 2-ст. смешанная (13–18, 32, 34, 40, 41) | шаг 1.2 с приборами дома; у зависимых СО Tо = T2 прибора отопления |
| 2-ст. последовательная (7–12, 33, 42, 43) | столбец «2-ст. последовательная» ЦТП с приборами дома |

**Порядок для дома любой схемы:** сброс к базе → испытательные ТО ГВС и Kgv (если есть закрытое ГВС) → циркуляция → (после шайбы ЦТП) сопло / шайбы → тепло. Дом с ИТП на одном приборе ТС (без раздельных \_OT / \_GVS): сначала разделить тепло QТС = Qсо + Qгв по нагрузкам или летнему потреблению и спросить пользователя.

## Ловушки и требования к калькулятору

Старый калькулятор выдавал часть рекомендаций, которые ломают модель. Новый должен их блокировать.

**Не рекомендовать:**

| Рекомендация | Почему ложная |
| --- | --- |
| Утечки 2 контура (α, Zrating\_calibr) по G3 − G4 ЦТП | дома возвращают почти всё → это ошибка расходомера (проверка 4) |
| Поднять Hnz\_obr, «Pobr ≥ Hzdan + 5», шайба после СО у ГВС-объектов | правила отопления к циркуляции ГВС неприменимы, СО нет |
| «Pobr > Pmax\_obr», когда по прибору давление в норме | превышение только в модели (сдвиг отметки) |
| Pcalibr\_pod / Pcalibr\_obr при одинаковом сдвиге давлений | «Калибровка» загонит отметку манометра в шероховатость труб |
| Предупреждение «Kcirc > 100 %» | 200–800 % нормально на суточных данных |
| % нагрузки ГВС ≠ 100 на суточных данных | часовая логика (было 117 %) |
| T12\_i = T21\_i + 5 как оценка | когда есть баланс ступеней, T12\_i считается (шаг 1.2) |
| Подгонка TО ЦТП под температуры при T1\_t ЦТП ниже прибора | причина — потери магистрали (шаг 6), ТО будет «фальшивым» |
| Правка Kso / T1\_r без флажка «исключение» | нарушает ограничения |

**Другие ловушки:**

- Сменили N\_schem и не пересчитали → JSON показывает результат старой схемы (проверка по Gverh).
- Два соседних JSON идентичны по результатам → правка не внесена или расчёт не запущен.
- Значения введены не тому объекту (было: график поликлиники у дома 33535) → сверять введённое с выданным по Sys.
- Regul\_G ЦТП — способ дросселирования, Regul\_T дома — регулятор ГВС: оба легко принять за регулятор отопления.
- Когда разбор по домам меньше, чем по прибору ЦТП, T2 ввода не дойдёт до факта — не дожимать параметрами ступеней.

**Что должен уметь новый калькулятор:**

1. Флажки ограничений: нагрузки, Kso, график домов, Kpoprav магистрали / квартала; источник разбора ГВС (ЦТП / дома); тип данных (сутки / час).
2. Проверки приборов 1–11 и чек-лист шага 0 с вопросами пользователю.
3. Один активный шаг; выдача таблицей «Sys · поле · сейчас · ввести» + список «не трогать».
4. Автопроверка критериев шага по новой выгрузке → «сошлось / поправка этого же шага».
5. Diff двух выгрузок: какие входные поля изменились и совпадает ли это с выданным.
6. Журнал правок и откат шага (вернуть предыдущие значения).
7. Итоговая таблица «модель / факт / откл.» и режим «второй день» (новые приборы без правок).

## Сайт: вход, история, шаги, ИИ

Калькулятор — сайт на сервере (фронт + бэкенд FastAPI + БД). Все расчёты цифр — в коде по формулам этого документа; ИИ только разбирает и объясняет.

**Вход и защита:**

- только HTTPS (Let’s Encrypt, TLS 1.2+, HSTS), HTTP → редирект; это защита от перехвата пароля и данных;
- пароль хранится только хешем Argon2id; минимум 12 символов;
- второй фактор TOTP (приложение-аутентификатор) + резервные коды;
- защита от перебора: не более 5 попыток за 15 мин с IP и на логин, растущая задержка, одинаковое сообщение об ошибке; fail2ban на уровне сервера;
- сессия на сервере, cookie HttpOnly + Secure + SameSite=Strict, новый ID при входе, выход по бездействию 12 ч, кнопка «выйти»; CSRF-токен на все изменяющие запросы;
- заголовки CSP, X-Frame-Options, Referrer-Policy; ключ API ИИ и секреты — только в переменных окружения сервера;
- по желанию: доступ только из своей VPN или списка IP; ежедневный бэкап БД; журнал входов.

**Главная:** «Новый расчёт ЦТП», «История ЦТП», «Схемы» (статусы схем).

**Расчёт ЦТП (проект)** = ЦТП + дата замера. Хранит: все вставки карточки и потребителей по итерациям, ручной факт ЦТП, ручные правки факта по Sys, выданные правки и что из них реально внесено (diff), статус каждого шага, ответы ИИ, комментарии. Автосохранение после каждого действия.

**История ЦТП:** список проектов (ЦТП, дата замера, схема, текущий шаг, статус: в работе / завершён / принят с отклонениями), поиск; «Продолжить» открывает текущий шаг; прошлые итерации — только чтение; экспорт JSON / отчёт; архив вместо удаления; новая дата замера для того же ЦТП = проверка вторым днём.

**Шаги как слайды:** ввод → шаг 0 → сброс → 1 → 2 → 3 → 4 → 5 → 6 → итог, каждый на своей странице. На странице: таблица «поле → сейчас → ввести», «не трогать», вставка свежих данных, критерии с отметками, вопросы по несостыковкам, кнопка «Разобрать с ИИ». Дальше — только когда критерии сошлись или нажато «принять с отклонением» с комментарием.

**Статус схем:** не отлажена / в проверке / откалибрована (дата, проект, отклонения, поправки к формулам). Откалибрована — только кнопкой «подтвердить» после итога. Исходно: ЦТП 2, потребители 4 и 26 — откалиброваны (Огородная, 87).

**ИИ по кнопке:** через бэкенд-прокси; в запрос — компактная выжимка шага (ЦТП, дома, критерии, выданные правки, методика шага), 15–25 тыс. токенов; модель выбирается в настройках; лимит расхода в месяц и счётчик стоимости; ответ сохраняется в проекте.
